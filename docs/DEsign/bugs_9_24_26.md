## Regression cover

New tests, each checked by mutation (reverting the fix must fail the test):

- `ShelterCeilingHeightTest` — shelter and corridor tiles disagree on ceiling height, and the raised constant really is raised.
- `SurfaceDecalPlacementTest` — no decal lands on a door or gate tile; out-of-range coordinates fail open.
- `ShopkeeperTrackerTest` — one merchant per level, and a fresh run can claim again. The related ordering fix (a chunk with nowhere to stand must not burn the level's only slot) is in `MazeChunkGenerator` and is **not** covered by a test; placement needs an `AssetManager`, so it is reasoned-about rather than proven.
- `ProgressionUnlockOverhaulTest` / `CodexDataAndFilteringTest` — retuned; the cap test now supplies telemetry that actually clears the raised bars (it previously met none of them, so the cap was never exercised) and the strata test is anchored on real scores rather than on the threshold constant.

## Not yet addressed

Two things found while working through the list, neither on it:

- [x] ~~**`Weather3DTest` is flaky** (~1 run in 10)~~ — fixed by `09195be`, merged from `feat/volcanic-sky-polish`, which culls splash droplets that drift under a roof. Diagnosis was: `WeatherRenderer.spawnSplash` checks the *spawn* tile is outdoors, then gives droplets outward velocity so they drift onto home tiles. Nothing wrong is ever drawn — the render path filters indoors — the test just inspects `getSplashDroplets()` rather than what is rendered.
- **Duplicate item templates**: both `SHIELD_LARGE`/`LARGE_SHIELD` and `SHIELD_SMALL`/`SMALL_SHIELD` exist as separate entries. That duplication is how their colour ladders drifted apart and produced the `COPPER` crash.
- When the player Starts a New Expedition from the main menu, it should wipe all save progress (progression) and all of that save data should only be applicable to that save file, there should be no global progression that exists outside of the context of a save file.
